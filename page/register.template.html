Evidence on the wire

match rules by kind

Rules, not applications — one application usually carries many. Tier B names dominate and are the band Encrypted Client Hello will erode; tier A payload prefixes read the protocol on the wire and survive it; tier C prefixes say who owns an address, never which application is using it.

A

Payload bytes

The first four bytes of the flow, matched against a known protocol magic — 4e58442d is "NXD-", NoMachine. Reads what is actually on the wire, so it keeps working when names are encrypted. But it identifies a protocol, not usually a product: it tells you this is FTP, not which application opened it.

B

Vendor-owned names

TLS SNI, HTTP Host and DNS names the vendor owns — youtu.be, ytimg.com. This is where application identity actually lives, and where nearly the whole corpus sits. It is also the band Encrypted Client Hello removes: when the name is no longer in the clear, these stop resolving.

— rules · — applications

C

IP prefixes

Address ranges their operator publishes. This says who owns the address, never which application is using it — behind a CDN thousands of unrelated services share one prefix. Useful to corroborate or narrow, never to decide alone, which is why these carry the lowest confidence in the corpus.

identity decisions, human-reviewed

An application count means nothing if the identities behind it are not distinct. Separator variants (epic-games / epicgames) merge automatically on a punctuation-stripped key — exact equality modulo separators, never similarity. Everything else is decided by hand and recorded here.
